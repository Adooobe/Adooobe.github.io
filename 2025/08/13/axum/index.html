Axum

Axum is a new(the latest version in community is v0.8, but there are also many crates under 1.0) API framework based on tokio with excellent design. That is also why I choose axum rather than Rocket, actix or some other popular web framework. However, there also many voice complaining the breaking changes of Axum which I believe that would be changed v1.0 realeased.

Handlers

The first thing is the parameters, in axum, they are called extractors which to extract different part in our HTTP request.

Extractors can be seen as several parts as follows:

  • Path related
    • Path parameter: parse id in /user/:id
    • Query parameter: parse ?a=1&b=2
  • Body related
    • Json
    • Bytes
    • String
  • Others
    • HeaderMap: headers
    • State<T>: shared state registered in router

Middleware

I use tower and tower-http as middleware layer in my program.

tower is a modular and reusable component library that provides protocol-agnostic middleware components. Its core features include:

  • Generic middleware: timeout handling, rate limiting, load balancing, etc.
  • Highly composable: easily combine multiple middleware through ServiceBuilder
  • Protocol-agnostic: suitable for any protocol that follows the request-response pattern

tower-http is a collection of HTTP-specific middleware based on tower, providing rich HTTP-related functionality:

Common middleware features:

  • TraceLayer: request tracing and logging
  • CompressionLayer: automatic response compression (gzip, br, deflate)
  • CorsLayer: Cross-Origin Resource Sharing (CORS) handling
  • TimeoutLayer: request timeout control
  • RequestIdLayer: generate unique ID for each request
  • AuthorizeLayer: authentication and authorization
  • SetRequestIdLayer: set request ID to headers
  • NormalizePathLayer: path normalization

Lessons

We know that Axum is based on tokio and hyper, which are the most famous frameworks of asynchronous I/O runtime in Rust. Asychronous programming is apprently different from simple synchronous one, with the former needing to consider more concurrent and blocking operations.

Let’s take look an exmpale in my program:

I have a HTTP connection pool for some kind of external API working in different tokio blocking threads(64 by default). For the first time, I set ONFIG.pool_max_idle_per_host to 10 which can be too small for the concurrent HTTP Request. Then I got a lot of OOM alerts of my service. Actions are as follows:

  1. change the global memory allocator to JeMalloc(at the beginning, it’s MiMalloc but I cannot find enough document on it) with default configurations.
  2. set malloc environement variables export MALLOC_CONF="prof:true,prof_active:true,dirty_decay_ms:0,muzzy_decay_ms:0"
  3. update max idel connections to 50/100 of HTTP connection Pool
